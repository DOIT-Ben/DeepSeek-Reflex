# 回归检查

在项目根目录使用 PowerShell 7：

```powershell
pwsh -NoProfile -File .\webview-host\tests\run-tests.ps1
```

先离线构建，再分别编译普通 DPI 和应用 DPI manifest 的测试程序。Node.js 仅用于模拟输入框聚焦脚本，可以用 `-NodePath` 指定程序路径；运行应用和构建 C# 均不需要 Node.js。

`-OutputDirectory <绝对路径>` 可指定证据目录，默认写入系统临时目录的独立 GUID 子目录。日志、预览图、测试程序及隔离偏好不写入源码目录。

覆盖偏好迁移与保存、热键冲突回滚、设置动画、窗口模式、原生命中测试、托盘收起、缓存圆角像素与 HWND 同步、缩放时 GDI 对象数量。测试创建自有窗口并使用隔离偏好，不加载官网或操作已有浏览器。Windows 拒绝测试窗口前台权限时，该项明确标记 SKIP。

首次引导检查覆盖后台启动延后、首次主动唤起、真实模态窗口中暂停与恢复快捷键、已排队热键不隐藏主窗、当前配置显示、完成/跳过、设置中重看和无法写入完成标记时的恢复行为。引导与设置的自有控件预览图保存在测试输出目录。

弹窗圆角检查通过主窗口的真实设置和帮助入口，分别在取消置顶、置顶、再次取消置顶时打开模态弹窗。检查四个圆角 HWND 的原生可见性、所有者、实际置顶层级和前后堆叠顺序，移动后仍保持对齐且只上传四次缓存图片；关闭后主窗尺寸、白色边缘和快捷键注册正常。另通过自有 HWND 故障注入，验证圆角原生层级与 WinForms 属性不一致时的恢复；夹具按应用顺序在创建句柄前设置无边框样式。这些检查同时在普通和高 DPI 运行，补足仅检查图片或 WinForms 属性无法发现的遮挡问题。

交互打磨检查覆盖快捷键录入提示、无效与重复按键、真实排队 Esc / Tab 消息、分段选择的方向键导航、小尺寸面板滚动与固定保存区、取词栏不重叠与收起还原、开关按下后移出及置顶动画快速反转。普通和高 DPI 都保存设置及取词栏的自有控件预览；这些证据不代表已验证所有设备的物理键盘与跨屏 DPI 切换。

`focus-tests.cjs` 使用模拟 DOM，检查聚焦不会读取或改写草稿；结果不能代替登录、物理键盘或跨应用取词验收。历史性能基准和交付证据留在项目外的任务归档，回归入口不重复运行基准。

## 缺陷边界与 CI 门禁

`run-boundary-tests.ps1` 编译生产代码，检查设置失败回滚、模态唤起、窗口状态、真实 MSAA/UIA 开关状态、DPI 消息、短引导布局、弹窗关闭以及隔离 WebView 的浏览器进程退出与重建。真实 WebView 测试使用独立资料目录并拦截外部导航，只终止夹具自身获得的浏览器 PID。

剪贴板检查通过内存适配器运行生产取词逻辑，不触碰系统剪贴板；草稿与聚焦检查运行生产代码生成的脚本，DOM 为模拟。它们不证明 Word 等所有应用均兼容，或真实官网的登录流程已经逐一验收。

CI 使用 `run-boundary-tests.ps1 -CoreOnly`，只运行无需交互桌面的分类、偏好、热键冲突、剪贴板适配器、草稿和聚焦检查。原生窗口、UIA、真实 WebView 故障注入在本机完整入口运行，CI 明确标记跳过，不把打包成功当成全部行为通过。

跨屏验收需两块缩放不同的实体显示器：往返拖动主窗，分别打开设置、引导与登录弹窗，核对四角、文字、按钮、拉伸指针和恢复位置；负坐标显示器也要测试。单屏的消息注入只能验证处理链路。

## 持续对话模式

`chat-mode-tests.cjs` 执行生产代码生成的脚本，覆盖逐条注入、去重、模式切换与草稿保留、选区、中文组词、粘贴、SPA 导航、输入框替换、来源与编辑器边界、一次性取词及模式目录。该检查也随 Core CI 入口运行。

`run-tests.ps1` 的普通／高 DPI 自有窗口检查包含常驻模式栏的最小宽度布局、取词栏收起后仍可用、设置保存及失败保全。模式截图输出到证据目录，不含官网内容。

```powershell
# 仅运行本次模式功能：Core + 真实 WebView + DOM 脚本
pwsh -NoProfile -File .\webview-host\tests\run-boundary-tests.ps1 -ChatModeOnly
```

真实 WebView 夹具拦截全部资源请求，使用隔离资料目录提供模拟聊天输入框；验证鼠标／Enter 连续提交、提示词唯一、原文恢复和取词绕过。此结果证明浏览器中的注入行为，不证明 DeepSeek 当前登录页面与模型回答质量。

v1.0.17 起，模式宿主夹具直接使用未替换的生产 WebView，检查默认不透明白色背景、初始化、模式切换、重载及跨屏草稿保留。此前的显式背景色接口异常已修复；发现时的替换夹具与失败记录保留于 [2026-10-12 快照](../../docs/testing/2026-10-12-chat-modes.md)，当前结果见 [发布验证](../../docs/testing/1.0.17-release.md)。

## 跟随鼠标唤起

```powershell
pwsh -NoProfile -File .\webview-host\tests\run-boundary-tests.ps1 -WakeOnly
```

`WakeTests.cs` 的纯几何检查随 Core 入口运行，覆盖负坐标、缩放、居中、屏幕空间限制和同屏保留。`-WakeOnly` 还运行隔离原生窗口的实际双屏移动；若不足两块连接显示器则明确 SKIP。使用生产 `Screen.FromPoint` 和窗口定位代码，但目标点由夹具提供，不移动系统鼠标或读取外部应用内容。

原生检查包括换屏居中、同屏位置恢复、显示中跨屏唤起、最小化／托盘隐藏、置顶、最大化与恢复、小窗／阅读尺寸、延迟取词目标、托盘排队目标、已有实例消息、手动拖动取消排队居中、圆角与焦点。模式 WebView 专项另验证实际跨屏后草稿与模式仍然存在。

证据输出在调用指定的隔离目录，未访问个人 profile、系统剪贴板或模型服务。实体快捷键、外部应用取词和显示器拔插仍需另行验收；本轮实际缩放及结果见 [2026-10-13 验证记录](../../docs/testing/2026-10-13-wake-placement.md)。

## 模拟 DPI 专项

`run-boundary-tests.ps1 -DpiOnly` 先把窗口稳定在目标显示器并同步真实 DPI，再注入模拟消息。检查仍要求精确的 150% 缩放、负坐标和建议宽高，不与同一次移动触发的真实 DPI 消息竞争。真实跨屏 DPI 另由 WakeOnly 验证。

v1.0.17 发布前在临时源码副本禁用 `WM_DPICHANGED` 处理分支，确认该专项在预期断言失败；原源码不参与变异修改。负例和完整门禁结果见 [发布验证](../../docs/testing/1.0.17-release.md)。
