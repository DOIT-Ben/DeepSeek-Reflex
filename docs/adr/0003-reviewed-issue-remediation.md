## D1：停止安装器的旧目录自动递归删除

删除必需安装段中针对 `Programs\DeepSeekFloat` 的自动 `RMDir /r`。本轮保留旧程序文件，包括旧托管文件；不承诺完成旧目录垃圾清理。当前安装写入和既有卸载白名单保持原样。这样即使安装目录等于旧目录、位于其子目录，或旧路径有用户额外文件，也没有这一步递归删除。

备选是新增规范化、目录关系与 reparse point 防护后按白名单清理。该方案引入新的迁移/删除职责及失败面，超出修复所需；保留少量旧程序文件是明确的保守代价。今后清理应另定迁移合同，不把用户文件视为可删除内容。

## D2：显式成功分支

旧 `DeepSeek.exe` 的 `FileOpen` 成功并 `FileClose` 后，显式 `Goto install_files`；失败仍进入原 `install_busy` 并有非零退出码。当前新 EXE、旧 Float EXE、旧启动器三种占用路径均保留，不靠删除旧文件绕过检查。

## D3：菜单量测与绘制使用相同文本语义

`TrayMenu` 的量测和 `TrayRenderer` 的绘制共同使用 `NoPadding | NoPrefix`；绘制继续采用原对齐、垂直居中和超长名称省略策略。内置短名称应完整显示，不通过恢复宽度地板或加大左右空白掩盖错误。职责留在菜单组件，不改 ChatWindow 的鼠标钩子、模式目录和发送逻辑。

## D4：设置页高度切换也必须拟合当前工作区

`ApplyDialogHeight` 统一将请求高度与当前位置/宽度组成矩形，在赋值前调用既有 `FitBounds`。工作区取当前窗口所在屏幕，沿用当前 scale；构造、进入指令、返回、保存指令等所有既有调用方共享这一逻辑。空间不足时由原滚动内容区承接，固定页脚保持可达。不开新设置项，不改变快捷指令保存/取消语义。

备选仅在 Shown 或返回按钮补一次修正会遗漏其他入口；全局缩小窗口则不能保证多屏和 DPI 条件，均不采用。

## D5：记住成功提交的联系方式，包括空值

发送前捕获 trim 后的联系方式，与该次 JSON 使用同一个值；成功响应后将该快照写入原 `feedback-contact` 偏好，包括空串。失败响应不改旧偏好。保留原“反馈已成功但本地偏好写失败仍显示成功”的语义，不重发已成功反馈。这样既可清除旧记忆，也不把 await 期间编辑的新值误记为本次提交值。

不新增联系人接口、自动发送、额外服务请求、成功重试或配置版本。发送期间重复提交等审查已识别的旧问题另行记录，不扩展本次实现。

## D6：顺序门禁、隔离和回退

先取得当前 ADR/阶段测试合同指纹的独立方案 PASS，再进入 I1。每阶段独立实现审查最多三次结论；方案审查最多两轮。成功即继续下一阶段，不以进度更新再次索取授权。单一状态所有者为审查记录。

安装回归从真实必需安装段生成 NSIS 隔离 fixture：文件路径及快捷方式重定向至新建临时目录，禁止真实注册表写入，快捷方式注册进程调用用替身；占用检查、分支、文件写入和清理指令保留原代码。用旧源码验证 fixture 能发现故障，再检查修复。不运行个人安装器。

原生回归编译真实受影响源码，仅在临时 Preferences 副本将 Root 初始化直接指向测试目录，不调用 `EnsureRoot` 的个人数据迁移。UI/绘制用真实 WinForms/GDI，反馈使用 mock poster；临时测试工具可支持单文件基线覆盖。补充相关既有 SettingsTests 回归时沿用同样隔离，所有 UI 测试串行、有界退出。

方案不改变持久数据结构；撤销本轮各阶段差异即可回退，保留既有文件。回退旧目录递归删除会恢复高风险，不能以自动回退方式重新执行安装。当前发行包、本机安装和远端 Issue 状态不随本地阶段通过而改变。
