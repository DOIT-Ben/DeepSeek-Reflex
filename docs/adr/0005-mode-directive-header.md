# ADR-0005：模式声明头——每轮注入当前模式守卫

**PROPOSED · 2026-11-05**。基线 main（ADR-0004 实施后）。

来源、影响与阶段/测试合同见 [来源与影响](0005-impact.md)、[阶段合同](0005-stage-tests.md)。方案门禁和实施进度的唯一所有者是 [审查与实施记录](0005-review.md)。本 ADR 不修改 ADR-0001~0004 的受检内容。

## 目标与边界

同一官网会话中切换聊天模式后，模型延续旧模式行为（如总结数轮后普通聊天仍带总结腔、继续压缩排版）。机理有二：①注入的前缀随消息发出后**永久留在 DeepSeek 服务器侧的会话历史里**，宿主无法回收；②切回普通对话时 `ChatModes.Prefix` 返回空串、注入器 `apply` 直接跳过（`ChatModeInjector.cs:32`），最需要压制的场景零防护。宿主是 WebView2 壳加官方页面，没有中间层可改写请求历史，唯一可用的作用面是**每条发出消息自身的文本**。

## D1：头的内容契约

`ChatModes.Directive(mode)` 运行时生成单行声明头，两种形态：

- 任务模式（内置被覆盖与自定义模式同形）：`【当前模式：{显示名}】以下指令为本条消息的任务；此前消息中出现过的模式指令已全部过期，不再执行。上文中的原文、译文、总结稿等材料内容仍然有效，可正常引用。`
- 普通对话：`【当前模式：普通对话】本条消息无任务指令，按普通对话直接回答；此前消息中出现过的模式指令已全部过期，不再执行。上文中的材料内容仍然有效，可正常引用。`

三要素缺一不可：只写身份（用户最初设想的"现在是X模式"）压不住旧指令的输出格式惯性；不作废声明则模型可能并列执行两套指令；不点名内容有效则模型可能把上文材料一并冷处理（丢翻译/总结上下文）。措辞采用状态描述（"已过期"）而非对抗命令（"忽略上述"），遵从度更高且不废后续显式切换（用户再说"总结一下"仍正常执行）。

## D2：三条消费链统一接线

- `ChatModes.Prefix(mode)` 改为 `Directive(mode) + "\n" + Instruction + 既有信封`；normal 分支从空串改为仅返回 Directive。持续注入 catalog 由 Prefix 生成（`ChatModeInjector.cs:6`），头自动进入每轮草稿；marker 前缀替换与 `adopt` 的首行 header 识别（`ChatModeInjector.cs:29`）以第一行为界，头单独成行正好成为一次性请求的 header。
- `PromptInserter.Compose`/`ComposeInstruction` 在指令前拼同一 Directive：取词三动作与持续注入措辞继续一字不差（延续 ADR-0002 单一措辞约定）。
- DSH 桥：宿主侧经 `ChatModes.Prefix` 组合，头自动生效，插件零改动。

normal 有头后，注入器 `state.mode==='normal'&&!state.marker` 的提前返回仅在无草稿时仍成立；有材料时 normal 草稿同样拼头再发送，`"Empty composers stay empty"` 注释语义保留——无真实材料永远不注入。

## D3：边界与后备方案

头由宿主常量生成：`modes.json` 的覆盖只改 Instruction，永远改不到头（防线系统级，TR-02）；`All` 数组文本不动（TR-01，延续 0004 的构建期提取约束）。注入可见性原则不变（chat-modes.md："提示词在输入时可见，而非隐藏改写请求"），头在输入框中原样可见。

已评估并搁置的替代方案：①用户手打"忽略上述"——对抗性写法遵从不稳且易过度泛化丢内容；②反代/中间层剥改历史——架构不符，messages 在 DeepSeek 服务器；③切模式自动开新对话+回填内容——确定性最强但打断会话连续性、回填内容取舍无自动判据、对官网页面结构的自动化耦合更重。若 S1 真机验收发现头不足以压制惯性（FR-03 不过），方案③升为正式提案重开 ADR。
