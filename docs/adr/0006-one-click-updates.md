# ADR-0006：GitHub Release 一键更新与安装重启

PROPOSED · 2026-11-07。代码基线 fbbcee8284346806e40100b1da37393dd422f6c6。影响见[检查报告](0006-impact.md)，门禁与实施证据唯一记录在[审查记录](0006-review.md)。阶段和测试合同内嵌于本文。

## 来源与范围基线

U1，2026-11-07，用户原话：“可以，兄弟，就按这个方案把一键更新和安装重启做出来，保留配置和登录状态，把下载失败、安装失败和未保存内容这些边界也测试好，做好后安装到本机给我体验。 用ADRskills实现。”前序已明确选择 GitHub Releases＋独立更新器、无需自建服务器。授权覆盖本地实现、必要隔离测试和本机安装；本轮不发布新 Release、不修改已有 v1.0.19、不部署反馈端或 DSH，不改变模型路由，不写第三方会话。

## D1：发布协议与信任边界

固定 https://api.github.com/repos/DOIT-Ben/DeepSeek-Reflex/releases/latest，仅稳定正式版、严格 vX.Y.Z。无 token、Cookie 或会话数据。版本不高于当前时不下载；拒绝预发布、无效版本、重复或缺失目标资产。采用 DeepSeek-Reflex-X.Y.Z-Windows-x64.zip，资产 size 必须正且 ≤64 MiB、GitHub API digest 必须为 sha256。ZIP URL 必须为本仓库该 tag 的精确下载地址；重定向最多 5 次，只允许 HTTPS 的 github.com、api.github.com、release-assets.githubusercontent.com、objects.githubusercontent.com，拒绝凭据、非默认端口和跨源逃逸。

请求总时限、读写超时、取消中止请求；元数据 ≤1 MiB。流式下载至当前任务 .part，必须满足声明字节数、上限及摘要后才转为可安装。失败删除本次不完整文件并保留有效候选，可重试；互斥状态避免重复请求、双下载及旧结果覆盖。默认后台检查每日一次，失败至少一小时退避；自动检查开关及时间单独存在 LocalAppData 更新状态，不改既有偏好格式。后台失败不弹错误框。

依赖 GitHub HTTPS 元数据与仓库权限，是发布来源的信任根；SHA 保证完整性，不冒充独立签名或 Authenticode。现有包未签名，本轮不增签名服务器。旧版没有更新器，首次需手动装一次带更新器的 v1.0.20；本轮本机新版本高于 GitHub 正式版 v1.0.19，不假造线上可更新版本。

## D2：包和磁盘事务

复用现有 21 项发行白名单（packaging/test-package.ps1），拒绝越界路径、反斜线、绝对路径、大小写重复、额外文件和 reparse 目标；只允许既定目录。总解压 ≤128 MiB，单文件 ≤32 MiB。验证内置 SHA256SUMS 的 20 条精确文件集合、全部文件摘要、VERSION、主程序 ProductName 和 ProductVersion。先验证后进入可安装状态；helper 再验证一次，读取 ZIP 期间拒绝并发写和删除。

包校验集合为 21 项，安装写集严格沿用 install.ps1 的 11 项：主 exe、exe.config、两份 WebView DLL、WebView2Loader、icon.ico、VERSION、LICENSE、THIRD-PARTY-NOTICES、WebView2-LICENSE、WebView2-NOTICE。其余 README、QUICKSTART、内部清单和 docs 图片只校验，不覆盖安装根的同名内容；uninstall.exe 与任何其它用户文件不动。11 项是已验证品牌安装的保留程序名，替换前备份并校验当前摘要；发现同名目录、reparse 或准备后外部改写时阻止安装，不静默覆盖冲突。

更新任务位于当前用户 LocalAppData 的随机任务目录；worker 是当前程序及必要依赖的外部副本，用 --apply-update 入口先于普通 mutex/UI 启动分派。无提权，无任意远程命令或目标路径入口。计划包含 task id、现有程序路径／摘要、父 PID 和启动时间、目标版本／ZIP 摘要；必须验证品牌、路径、父进程身份，目标不能为磁盘根、用户根或个人资料目录，拒绝安装根及其受管后代 reparse points。

helper 在安装目录内创建本次专用随机 staging／backup，保证备份和替换同卷。先验证并暂存全部文件、备份当前受管文件、落盘恢复记录，成功才发 ready 握手；父程序在 ready 之前不退出。任何准备失败均保留原主进程。父退出等待有 30 秒上限，可通过本次 abort 信号取消，绝不强杀。worker 在发 ready 前持有全局更新屏障 mutex，直到替换／回退结束才释放；父退出后再取得 Host mutex。正常程序入口在取得 Host mutex 之前和之后都核对更新屏障，命中则不加载 UI 或启动浏览器。两次检查覆盖“新实例刚检查完、父恰好退出”的竞争；worker 取得 Host 锁失败则停止而不修改文件，不强杀竞争实例。测试使用编译期注入的独立 mutex 名称，生产协议不允许计划文件重命名屏障。

替换逐项使用同卷原子 Replace／Move；主 exe 最后。备份数据和每次日志临时文件先 Flush(true)，日志同卷原子替换，再执行文件替换；每项替换前后记录意图／结果与新旧摘要，失败逆向恢复旧文件，首次新增文件只在确认属于本次摘要时删除。保留不可确认的内容并报告恢复未完成；恢复记录和备份必须留下，在下次启动先处理未完成事务。正常入口只做基础 .NET 引导，UI／ChatWindow 放到禁止内联的独立方法；在加载 WebView 依赖前检查本安装根的 active 事务指针。若旧 worker 已退出且日志为准备／提交中，启动任务目录中已校验身份的独立 worker 副本进行恢复，当前引导进程退出释放文件；恢复入口核对本次引导 PID／启动时间，只回退未提交事务。current item 记录允许按新／旧摘要判断替换是否已发生；目标已是旧摘要可幂等跳过，未知摘要则保留备份并进入 RecoveryRequired，阻止混合版本 UI 启动。恢复日志本身同样采用写前记录与原子替换。测试强制终止真实 worker 后再启动引导程序，确认恢复先于 UI；实际断电不冒充已实测。只在提交成功且主 exe 版本匹配后重启；失败恢复成功时启动旧版。磁盘满、文件锁、退出超时、helper 启动失败不得被报告为成功；重启失败独立提示，可手动打开已验证程序。只有 HKCU 卸载注册项的 InstallLocation 精确匹配本次安装时，提交后才尽力同步 DisplayVersion；便携副本不碰个人安装注册项，此附加元数据失败单独报告，不把已验证文件提交误报为失败或强行提权。Preferences.Root 与 WebView profile 不在事务目标中，绝不读取或修改用户聊天／登录数据。

## D3：UI 与未保存门禁

设置增加“版本与更新／检查更新”，进入单实例更新窗，不关闭设置。状态：Idle→Checking→Available/Current/CheckFailed→Downloading→Ready/DownloadFailed→Preparing→退出→Applied/RolledBack/RecoveryRequired。按钮随状态变化，下载可取消，失败可重试；安装准备期间禁止再次安装或关闭更新窗来丢失结果。共用位置、主题和 EditorTextBox，窄屏可滚动。

安装之前检查设置一般字段、模式／指令列表及当前编辑器、正在录入的快捷键。聊天只读取可编辑框的“是否非空”布尔值，不传输内容；无法确认时阻止安装。其它帮助／反馈／登录等自有窗口仍打开时要求先关闭，避免丢失其状态。阻止安装时说明需要处理的位置，不提供静默丢弃。下载期间可以继续工作，进入准备先暂挂主窗交互与热键，ready 后再次核对，发现新草稿则 abort 并恢复原交互范围。窗口只提供既有状态查询和正常退出，不承担网络或磁盘事务。

自动发现新版只做一次本地提示并可进入更新窗；有未保存内容时继续等用户处理，不自动重启。检查和下载均不改变网页焦点／草稿。启动读取事务结果，显示版本或恢复失败信息，不把安装成功和重启成功混同。

## D4：备选与后果

不采用静默 NSIS：当前脚本忙碌时拒绝且无全事务回退。不采用外部常驻服务／自建服务器：当前仅需 GitHub 分发，无需额外权限和运维。不引入第三方更新框架：当前固定 .NET 工具链和单一 ZIP 协议可复用已有受管文件、原子替换与包校验。新增网络、包、事务和协调模块是目标必需；禁止把协议／下载／磁盘循环继续堆进 ChatWindow 或 SettingsDialog。下载网络失败（含 GitHub 不可达）不降级到未经验证的镜像。

## 阶段及验收合同

S1：协议、下载、校验、worker 与事务。写集 UpdateFeed.cs、UpdatePackage.cs、UpdateTransaction.cs、Program 的早期分派、必要压缩程序集引用及更新测试。验证正式／旧／预发布、畸形 JSON、错误来源、限流／404／超时／中断／取消、字节数／摘要不符、ZIP 越界／重复／缺项／超限、品牌／版本、准备失败、进程身份、退出超时、锁文件中途失败回滚、主退出竞争启动、强制终止 worker 后再次引导恢复及恢复失败保全、同名 README／docs／非托管文件保留、注册路径不匹配时无写入、成功安装和真实子进程重启；保留负例或故障注入。独立实现审查通过后进入 S2。

S2：UpdateCoordinator／UpdateDialog、设置入口与脏状态、根窗门禁／正常退出、自动检查状态、本地版本 v1.0.20 与文档。测试设置各页、聊天／反馈草稿、用户在下载期间修改内容、重复点击、关窗／退出、主题／DPI／焦点和旧功能回归。禁止实体全局键测试在未经协调的前台输入中运行。独立实现审查通过后备份并安装本机，核对配置／登录保护文件与运行版本，查看实际更新 UI。

验收分层：真实 GitHub v1.0.19 元数据和 ZIP 下载校验，不执行或发布它来冒充升级；隔离本地 HTTP 故障和严格元数据协议；隔离带品牌版本的旧／新 fixture 程序及完整受管 ZIP，真实 worker 安装、回滚、重启哨兵与非托管文件保留；本机只安装本轮实现并检查正式源结果。不得把模拟 feed 或测试版本伪装成已公开 v1.0.20。所有预定必需项未执行、被跳过或失败时阶段不得 PASSED。

所有阶段、轮次和实际证据记录在 0006-review.md；阶段通过不自动提交／推送／公开发布。开始时主树干净，沿用主活动工作树与依赖；规划新增 ADR 属本任务，不触碰无关工作。
