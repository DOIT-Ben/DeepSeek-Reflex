# ADR-0001 原始需求与确认记录

记录日期：2026-10-05。来源为本项目维护者在当前会话中的直接请求与选择；此文件只保留本 ADR 必要的片段，不收录账户、联系邮箱、私人对话或全局环境。

## U1：扩展方向及工作顺序

> 针对这个小工具还有什么好玩的一些地方，就是还可以再扩展一下？？
>
> 来吧，兄弟，先写好ADR，然后开始设计

此前推荐先做“贴边收纳＋自定义快捷指令”。本记录不把推荐当作用户确认，确认依据为 U2。

## U3：用户批准实施的计划摘录

> 基于当前 v1.0.12，先完成 ADR、独立审查、可点击交互稿，保留已经认可的窗口样式。
>
> 本轮先设计，实际程序接入和安装包更新放到后续实施阶段。
>
> ADR 以 PROPOSED 落盘；独立审查通过后开始交互稿设计。审查意见单独记录，不自行宣布通过。

> 设置中新增“贴边收纳”，默认关闭。
>
> 开启后，拖动窗口并在屏幕左右外边缘 12 DIP 内松手，收成约 32×80 DIP 的蓝鱼标签；调整窗口大小不触发收纳，多显示器接缝不触发。
>
> 点击标签、使用现有唤起快捷键或托盘入口，恢复收纳前的位置和尺寸；鼠标经过只显示悬停反馈。
>
> 打开设置、引导或取词时先展开。最小化、关闭和快捷键收起方式继续遵循现有设置。

> 取词栏固定两行：第一行“翻译／解释／提问／更多指令／关闭”；第二行放状态、填入和复制请求。
>
> 设置面板增加“管理快捷指令”子页面，支持新增、编辑和删除；使用同一个面板外框。
>
> 请求填入后由用户确认发送；输入框已有用户草稿时保留草稿，并提供复制请求。

> 自定义指令保存为独立、带版本的本地配置；取消编辑不落盘，保存失败保留编辑内容。
>
> 沿用当前蓝鱼 Logo、白蓝配色、字体、主窗 22 DIP 圆角及按钮反馈。主窗口不增加常驻指令按钮。
>
> 交互稿为自包含 HTML，使用演示内容和内存状态，明确标注“交互预览”。

> 原型验收只证明交互设计；原生拖动、圆角性能和真实取词由接入程序后的测试验证。
>
> 后续程序修改继续按既有约定完成提交、推送、安装包更新和本机安装。

## U4：保留的已批准基线

- 用户已认可当前小窗外观、居中品牌、左右工具布局及顺滑圆角。
- 自动选词弹出独立浮窗已被用户明确关闭。本 ADR 不将贴边收纳与该功能关联，也不重新开启它。
- 此次无需截图提问、独立指令面板、新 Logo、新 API Key 或反向代理。

附件说明：本轮没有新增设计参考附件；历史截图用于理解既有外观，未复制到公开仓库。原型使用仓库内已批准的 Logo 及人工编写的演示聊天内容。
