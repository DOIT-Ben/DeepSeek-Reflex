# BUG-013 模拟 DPI 消息与真实跨屏缩放竞争导致假失败

- 状态：已修复关闭
- 优先级：P3
- 发现：2026-10-12／13 本机边界回归。
- 影响：本机测试与发布门禁；不是新的生产跨屏布局缺陷。
- 边界：模拟消息夹具与真实双屏检查，不代替物理拖动／按键验收。

## 现象

同一次操作注入 150% 消息并把窗口从 150% 显示器移动到实际 200% 显示器；系统随后发出真实 DPI 更新。原断言仍要求最终值 150%，出现位置和圆角正确但断言失败的情况。目标已经在同屏时模拟值又可保留，结果依赖测试开始位置。

## 复现

旧代码与本轮代码均观测过 `X=-720,Y=40,Width=960,Height=1240,scale=2,aligned=True`。在同屏路径又观测 `720×930,scale=1.5`。基线源码重新编译也能复现，不属于新唤起定位功能引入的回归。

## 代码／行号证据

受检提交的 [BoundaryTests.cs:87](https://github.com/DOIT-Ben/DeepSeek-Reflex/blob/59394346add5f7d1a774fae0ead2289aea1e60c7/webview-host/tests/BoundaryTests.cs#L87) 在消息处理与跨屏位置改变之间未隔离条件；断言依赖模拟 DPI 覆盖系统后续更新。

## 根因

混合了两种合同：模拟消息应按其参数处理；实际跨屏应跟随 Windows 真实 DPI。一个最终值不能同时验证两者。

## 修复方案

先固定目标显示器并同步真实 DPI，再注入模拟消息。保留严格的 150% 检查，增加 top 与精确宽高检查。实际 150%／200% 往返仍由 WakeTests 独立验证。

## 验收标准与结果

模拟消息在稳定目标上应用 150%、负坐标和精确建议矩形；双屏原生检查验证真实缩放、居中和逻辑尺寸。临时源码副本禁用 `WM_DPICHANGED` 分支后，专项在预期断言失败，证明没有通过忽略处理来消除失败。完整回归退出码 0；见 [发布验证](../testing/1.0.17-release.md)。没有新增跨问题经验条目。
