# BUG-014 设置与反馈的输入表面叠了多层灰底

- 状态：已修复关闭（2026-11-05，模拟 DPI 验证边界内；实体跨屏未涉及本项）
- Issue：https://github.com/DOIT-Ben/DeepSeek-Reflex/issues/6
- 优先级：P2
- 发现时间与方式：2026-11-04，用户截图指出设置里的「聊天模式」名称行和「选中文字取词」快捷键；2026-11-05 对照工作区源码与 `docs/ui-style-guide.md`。
- 受检版本：基线提交 `e19bfdc`（`main`）。截图上的静止描边与该提交一致。工作区另有未提交的填充式改动，已去掉静止描边，但没有去掉套层。下面的行号是 2026-11-05 工作区阅读位置，不是已推送提交上的行号。
- 影响面：设置的聊天模式、快捷指令、快捷键行，以及反馈窗的输入框。官网聊天正文和 DSH 插件样式不在本项。
- 证据边界：用户截图两张，加上上述文件的绘制与布局代码。没有对运行中的窗口做取色或像素测量，因此不把「白方块的精确像素」写成已测量事实。浅色、深色、100% 与 150% 的修复后截图都还没有。

## 现象

同一块设置表面上同时出现页面白、卡片灰、输入灰和另一块更浅或更白的矩形，静止时还能看到边框。

- 聊天模式：名称行左侧有一块小的白矩形，压在输入框左缘上；名称、提示词贴着输入框边界。输入框、编辑卡和「新增模式」各自一块灰。
- 快捷键：「选中文字取词」下面的 `Ctrl+Shift+D` 是一个带边框的矩形，坐在另一层灰底上。
- 「编辑」「新增模式」看起来像灰条，不像文字动作。`新增模式` 被拉成接近整行的一条，而不是和「保存条目」「恢复默认」并排的按钮。

## 复现

1. 打开当前安装或由 `e19bfdc` 构建的设置。
2. 进入「聊天模式」，看名称、提示词和「新增模式」。
3. 回到常规设置，看「选中文字取词」的 `Ctrl+Shift+D`。
4. 对照：主按钮「保存模式」是唯一的蓝色实心按钮；其余动作不应再各铺一块灰。

工作区这版去掉静止描边后，边框会轻一些，但灰块套灰块仍在。不能把「已经不画边」当成此项关闭。

## 代码/行号证据

样式规范已经写明宿主规则：默认不画静止描边，层次只靠页面、卡片和输入底；唯一边框是输入聚焦环。见 `docs/ui-style-guide.md` 的「填充式基座（2026-11-05 起）」。

实现没有遵守这套规则：

- `webview-host/SettingsPanelControls.cs:107`：非分段按钮的填充色固定取 `Card`，不使用调用方设的 `Well`。
- `webview-host/SettingsPanelControls.cs:114`：先把控件矩形清成 `BackColor`，再在里面填一个圆角 `Card`。输入框因此至少有两层不同的灰。
- `webview-host/SettingsDialog.cs:285` 与 `:292`：聊天模式的名称、提示词是 `InputFrame` 按钮，背景写成 `Well`，里面再放原生 `TextBox`。快捷指令编辑卡 `:191`、`:198` 相同。
- `webview-host/SettingsDialog.cs:557` 与 `webview-host/HotkeyBox.cs:14`：快捷键外框背景是 `Well`，内部 `HotkeyBox` 背景却是 `Card`。
- `webview-host/SettingsDialog.cs:550`：字段标签背景固定为页面白 `Back`。标签放在灰卡片上时会抠出白块。
- `webview-host/SettingsDialog.cs:521`：`ArrangeModes` 把模式下每一个子控件的宽度都设成「容器宽减左边距」。`新增模式` 因此被拉成整行灰条，并和后面的动作按钮重叠。
- `webview-host/FeedbackDialog.cs:20`：反馈正文和联系方式使用同一套 `InputFrame` 按钮。
- 已提交的 `e19bfdc` 还在卡片、分段控件和非幽灵按钮上 `DrawPath` 描边，输入框使用更深的 `InputBorder`。这解释截图里的实线边框。工作区删除了 `Outline` 和这些静止描边，但没有改掉上面的填充和嵌套。

## 根因

输入框不是一个表面，而是三层控件叠出来的：灰卡片、当作输入框用的 `PanelButton`、按钮里面的原生文本框。按钮绘制不看 `Well`，标签又使用页面白，所以每一层都自己贡献一块颜色。快捷键行是同一结构。布局再把幽灵按钮拉满宽，灰按钮就变成另一条灰带。

## 修复方案

一次收完，不要只删某一圈边。

- 宿主自绘表面只留四级：页面 `Back`、分组 `Card`、输入 `Well`、主按钮 `Accent`。静止态不描边。`InputBorder` 继续只留给插件 token，宿主不画。
- 输入框改成只负责圆角填充的容器，不再用 `PanelButton` 装原生文本框。文本框无边框，底色与容器的 `Well` 相同，并完整落在圆角内部。
- 聊天模式、快捷指令、快捷键、反馈四处共用这个容器。聚焦时只画一圈强调色，不与灰边并存。
- 卡片上的标签使用卡片色或透明，禁止页面白。
- 幽灵动作（编辑、新增模式、保存条目、恢复默认、返回）不铺 `Card`、不描边。动作行可以占满内容宽度，但三个按钮保持并排，不得互相覆盖。
- 主按钮仍只有保存一类。深色用同一套角色，不另加灰色。
- 不改官网页面，不改 DSH 插件样式。

## 验收标准

- [ ] 浅色与深色、100% 与 150% 各有一张设置截图：聊天模式的名称和提示词、快捷键 `Ctrl+Shift+D`、反馈输入框。每一处输入只有一块 `Well`，没有内嵌白块或第二圈边。
- [ ] 未聚焦时测不到静止描边；聚焦时只有一圈强调色，灰边和焦点环不同时出现。
- [ ] 「编辑」「新增模式」不是灰条；新增、保存条目、恢复默认并排且不重叠。
- [ ] 卡片上的「名称」「提示词」不再是白底标签。
- [ ] 四类输入共用同一容器，不允许聊天模式修完、快捷键或反馈仍用 `PanelButton`。
- [ ] 只去掉描边、或只改一个页面，都不能关闭本项。

## 实施记录（2026-11-05 关闭）

按修复方案一次收完，逐条对照：

- **单一填充来源**：`SettingsPanelControls.OnPaint` 的填充色改为 `Segment?Back:InputFrame?BackColor:Card`——输入井容器尊重调用方设置的 `Well`，圆角填充与内嵌无边框文本框（同为 `Well`）合成一块表面，Clear 角与圆角填充分色问题一并消失。
- **容器保留 `PanelButton` 的说明**：记录原方案要求弃用 `PanelButton`；实施保留该类但使其 `InputFrame` 形态成为纯填充容器（填 `BackColor`、聚焦环外无任何描边与二次填充），验收结果与"只负责圆角填充的容器"一致，且避免复制一份动效/聚焦环代码。这是对处方步骤的偏离，非对验收标准的偏离。
- **快捷键行**：`KeyRow` 给 `HotkeyBox` 显式 `BackColor=Well`，外框与录入框同色。
- **标签**：`LabelAt` 与全部错误槽/hint 已改 `Color.Transparent`（2026-11-05 上午批），卡面不再抠白块。
- **按钮拉伸**：`ArrangeSubpage` 只拉伸带右锚定的行（标签/列表/编辑卡）；「新增模式」「保存条目」「恢复默认」「编辑/删除」保持并列放置宽度，不再拉成整行灰条。此条是本 bug 记录与 issue 截图抓到、此前像素审查漏判的问题。
- **反馈窗**：`bodyFrame/contactFrame` 走同一 `InputFrame` 填充修复，无需单独改。

## 追加整改（2026-11-05 晚，配色收敛 + 字段原生样式）

用户复核后仍否掉"灰井垫白卡"的层次：一个页面同时出现页灰/白卡/灰井/选中灰/淡蓝按压五种面，且多灰带蓝偏。两步收敛：

1. **底色种类 7→4**：全应用浅色只剩页 243 / 卡白 / 交互灰 236（悬浮=次级钮）/ 选中 229，全部 R=G=B；淡蓝按压态、蓝灰井、蓝灰开关轨道、蓝灰插件边框（InputBorder 146 灰）清零，深色同构（32/41/48/58）。
2. **字段改 Win11 原生样式**：`InputFrame` 不再填灰井——白色字段面直接贴页，底部 1px 安静下划线（新 `FieldLine` 204 灰），聚焦变 2px 强调蓝线；字段面不做 hover/按压变色；模式/指令编辑器去掉外包白卡，字段直接排在灰页上。原先"聚焦画整圈强调环"改为下划线语义。

证据：`%TEMP%\reflex-0004-acceptance\neutral\`（states 特写像素验证 243/229 纯中性、设置/模式页浅深成对、ACCEPTANCE PASS）；插件 `npm run build`+check+test 通过；default 轮 419 项全绿（high-dpi 因真机桌面被占用在物理点击测试处中止，测得 179 项全过，配色改动无数值颜色断言依赖）。
